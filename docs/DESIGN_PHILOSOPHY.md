# Design Philosophy

## Core Principles

### 1. Complete slices over breadth
Finish MVP-1 before MVP-2. A working vector chat beats a broken hybrid pipeline. The assignment-giver explicitly prefers **2 complete features over 4 half-done ones**.

### 2. Backend-first, curl-before-UI
Every backend capability must work via `curl` before any frontend is built. The UI is a thin consumer of API metadata — it never invents sources or graph paths.

### 3. Provenance first
Every entity, relationship, and chunk must trace back to `(documentId, chunkId, pageNumber?)`. Source attribution is not a UI afterthought — it is a data model requirement from day one.

### 4. Grounded by construction
The LLM only receives retrieved context. Empty retrieval → explicit "I don't know", not a fabricated answer. Citations `[S1]`, `[G1]` are assigned by the backend, not generated by the LLM.

### 5. Document as you go
README, IMPLEMENTATION, FEATURES, and AI review files are updated per commit — not in a last-minute documentation dump.

### 6. Own every line
If you cannot explain a module in a code review, refactor until you can. AI generates code; the developer owns the decisions.

### 7. Minimal dependencies
- pgvector over Pinecone (local, no SaaS)
- SSE over WebSockets (one-way stream)
- In-process ingestion over Bull/Redis queue (for must-have)
- Redis used optionally for embedding/response caching (assignment enhancement)
- LLM extraction over spaCy (TypeScript-only stack)

## Modular Service Boundaries (NestJS)

| Module | Single responsibility |
|--------|----------------------|
| `DocumentsModule` | Upload, metadata, status |
| `IngestionModule` | Parse, chunk orchestration |
| `ExtractionModule` | LLM entity/relationship extraction |
| `GraphModule` | Neo4j read/write/traverse |
| `EmbeddingsModule` | OpenAI embedding calls |
| `VectorModule` | pgvector search |
| `RetrievalModule` | Hybrid merge + context builder |
| `ChatModule` | Prompt assembly + SSE streaming |

## AI-Assisted Development Approach

1. **Plan** the module (files, API, test) before prompting AI
2. **Implement** with Cursor agent/chat
3. **Verify** manually (curl / browser)
4. **Document** decisions in AI review file
5. **Commit** incrementally with clear message
6. **Gate** — only proceed when current slice works
